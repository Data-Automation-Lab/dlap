# Upgrading to the Spring Boot 4.1 platform

What an operator sees when moving a DLAP deployment from the Spring Boot 3.2.5 build to the
Spring Boot 4.1.1 build (BOOT-01, ADR-0065 and ADR-0066). The REST contracts, the Kafka message
formats, the database schemas and the Flyway history do not change. Read this before you roll the
new images out.

Why the upgrade happened: Spring Boot 3.2 has had no free security fixes since 2024-12-31, and
Hibernate ORM 6 is LGPL-2.1 (Q-105). Spring Boot 4.1 brings Hibernate ORM 7, which is Apache-2.0.
Free support for the 4.1 line ends 2027-07-31.

## What to do

1. Rebuild every image from this build. All eleven services and the new-ui JVM move together:
   the shared library `da-protos` is built for Spring Boot 4 and does not run inside a Spring
   Boot 3 service.
2. Remove the environment overrides listed under [Settings that changed](#settings-that-changed)
   from your own compose overrides, Helm values or `.env` files, or rename them.
3. No database step. There is no new Flyway migration and no new `dlap_common` delta. Running
   `deployment/platform/database/upgrades/run-upgrades.sh` is harmless and applies nothing new.
4. Kafka: the clients are Kafka 4.2, which talk to brokers from Kafka 2.1 on. The compose stacks
   ship Kafka 3.5 (Confluent Platform 7.5.3), which is fine. A broker older than 2.1 must be
   upgraded first.

## Settings that changed

The services' own `application.properties` and `application.yml` already carry the new names. You
only act if you override one of these yourself.

| Setting | Change | Where it applied |
|---|---|---|
| `spring.http.converters.preferred-json-mapper=jackson2` | New in every service. Keeps Spring MVC, the Feign clients and the `RestClient` on the Jackson 2 `ObjectMapper`. Do not override it. | all 11 services |
| `springdoc.api-docs.version=openapi_3_0` | New in every service. springdoc 3 writes OpenAPI 3.1 by default; the documents stay OpenAPI 3.0.1, as before. | all 11 services |
| `spring.jackson.*` (env `SPRING_JACKSON_*`) | No longer configures the `ObjectMapper` the services use. The same settings are now `spring.jackson2.*` (env `SPRING_JACKSON2_*`). `spring.jackson.*` configures Jackson 3, which serves no HTTP body. | da-discovery dev profile (`indent-output`) |
| `management.zipkin.tracing.endpoint` | Renamed to `management.tracing.export.zipkin.endpoint`. Read only when a Zipkin exporter is on the class path, which no DLAP image ships. | da-discovery dev and prod profiles |
| `management.endpoint.<id>.enabled` | Removed. Use `management.endpoint.<id>.access` (`none`, `read-only`, `unrestricted`). | da-discovery dev profile (`prometheus`) |
| `spring.jpa.hibernate.naming.implicit-strategy` | The Spring class moved: `org.springframework.boot.hibernate.SpringImplicitNamingStrategy` (was `org.springframework.boot.orm.jpa.hibernate...`). An override with the old name stops da-discovery at startup. | da-discovery |
| `spring.cloud.stream.function.autodetect=false` | New. Keeps Spring Cloud Stream from binding Spring Shell 4's `ThemeActive` supplier; see [da-discovery](#da-discovery). | da-discovery |
| `spring.shell.noninteractive.enabled` | No longer exists in Spring Shell 4. Nothing replaces it; see [da-discovery](#da-discovery). | da-discovery |
| `spring.dao.exceptiontranslation.enabled` | Renamed to `spring.persistence.exceptiontranslation.enabled`. No DLAP file sets it. | none |
| `spring.devtools.livereload.enabled` | Deprecated in Spring Boot 4.1, still read. DevTools is not in any image. | da-discovery dev and prod profiles |
| `server.undertow.*` | No effect any more: Undertow is gone. No DLAP file sets it. | da-discovery |

The check behind this table: every key in the services' `src/main/resources` and test
resources, the compose files and the `.env` examples, compared with the "Deprecated" and "Removed"
tables of the Spring Boot 3.3, 3.4, 3.5, 4.0 and 4.1 configuration changelogs on the Spring Boot
wiki. Settings of other projects (springdoc, Spring Cloud, JHipster, ShedLock) were checked
against their own release notes.

## Behaviour an operator can see

### HTTP

- JSON bodies are unchanged: the services keep Jackson 2 with the Spring Boot defaults they had
  (ISO-8601 dates, unknown properties ignored). `ProdProfileContextTest#httpJsonStaysOnJackson2`
  checks this in ten services.
- Every service runs on Tomcat 11 (Servlet 6.1). da-discovery ran on Undertow before; Tomcat's
  defaults now apply to it (for example 200 request threads).
- `GET /v3/api-docs` answers 200 on every service where springdoc is enabled. On Spring Boot 3 it
  answered 500 in ten services because an old `swagger-annotations` jar came in with the unused
  Confluent serializer (Q-272). Access rules did not change: the document needs a token where it
  needed one before, and da-discovery serves it only with the `api-docs` profile.
- The OpenAPI documents now carry the constraints the request validation already enforced
  (`minLength`, `minItems`, `minProperties`, `format: email` from `@NotBlank`, `@NotEmpty`,
  `@Email`), the `text/csv` response of the reporting CSV export, the `subOptions` field of the
  catalog `FilterOptionDTO` and a `name` on the bearer security scheme. Requests and responses
  are the same; the documents describe them more completely.

### Actuator and metrics

- `/actuator/health` stays public and its JSON shape is the same. The liveness and readiness
  groups were already switched on in every service.
- `/actuator/prometheus` is written by the Prometheus Java client 1.x (Micrometer 1.13 and later).
  Series names and labels are unchanged; the text no longer has a comma after the last label
  (`PublishFailureMetricsTest`). The platform Prometheus and its alert rules need no change.

### Persistence (Hibernate ORM 6.4 to 7.4)

The schemas are unchanged and every service still starts with `ddl-auto=validate` against the
Flyway schema. These Hibernate changes reached DLAP code or tests and were handled:

- A native query returns SQL dates as `java.time` types (Hibernate 7.0). The policy engine's
  daily compliance history read the day bucket as `java.sql.Date` and would have failed; it now
  prints either type as `yyyy-MM-dd`, as before.
- Saving an entity with a generated id and a preset id is a merge, and since Hibernate 6.6 that
  merge fails optimistic locking when no row exists (it used to insert). The reporting service's
  create paths for report definitions and notification preferences now clear a client-sent id,
  so such a request still creates a row with a new id. Create paths of entities with assigned
  ids (compliance controls, report types, service configs) behave as before.
- An element collection that is emptied in the same session in which its owner was persisted
  is not deleted at flush on Hibernate 7.4.5 (also seen on 7.4.13). Emptying it in a later unit of
  work, which is what every DLAP update request does, deletes the rows (policy engine
  `EventSubscriptionRepositoryDataJpaTest`). Code that persists and then empties a collection in
  one transaction must flush and reload in between.
- `connection_parameters` of admin-service cloud connections is mapped with Hibernate's own JSON
  type instead of hypersistence-utils; the jsonb text it reads and writes is the same.
- Hibernate ORM 7 also rejects some mappings it used to ignore (misplaced annotations,
  converters on ids), refuses refresh or lock of detached entities, and makes `getSingleResult()`
  throw on duplicate rows. No DLAP mapping or query hit these in the test suite.

### Scheduling

ShedLock 7.10.1 uses the same `shedlock` table and the same `usingDbTime()` provider configuration
in da-discovery and da-logingest; the lock tests (`ScheduledDiscoveryTriggerLockTest` and
`LogEventRetentionSweeperTest`) pass.

### Kafka

- Message formats are unchanged: JSON payloads keep the Jackson 2 serializer, protobuf payloads
  keep their wire format. Spring Kafka 4 prefers Jackson 3 for the components it picks itself when
  both are present. Every DLAP producer and consumer names its value serde: the Jackson 2
  `JsonSerializer` and `JsonDeserializer`, or String serdes around JSON that the Jackson 2
  `ObjectMapper` writes. The listeners read only the built-in topic, partition and offset headers,
  so none of those defaults is used.
- When a record fails and is due for another attempt, the error handler now throws Spring Kafka's
  internal `RecordInRetryException` instead of a `KafkaException`. The container still seeks back
  and redelivers; only the exception type in a debug log differs.

### da-discovery

- Undertow is replaced by Tomcat, see above.
- Spring Shell 4: a regular start (no arguments, or only `--option` arguments) never reaches the
  shell, as before. A shell command (`java -jar da-discovery.jar list-jobs ...`) runs once,
  non-interactively, as it did on Spring Shell 3 when arguments were given
  (`ShellRunnerConfigurationTest`).
- The locale cookie `NG_TRANSLATE_LANG_KEY` is read by Spring's cookie resolver. The Angular
  quoting the JHipster resolver handled does not occur with the React UI; a value that does not
  parse falls back to the default locale.
- Spring Cloud Stream function autodetection is off (`spring.cloud.stream.function.autodetect=false`
  in `config/application.yml`). No binding is configured, but Spring Shell 4's `ThemeActive` bean is
  a `Supplier`, which Stream would otherwise bind as a Kafka source polled every second
  (`themeActive-out-0`); with Kafka unreachable that kept the service from turning healthy.
- The HTTP clients the service builds itself (`RestTemplate` beans, the NiFi, Spark and catalog
  clients, the admin-service `RestClient`) keep Jackson 2 for JSON through
  `Jackson2ClientConverters`. Without it Spring Framework 7 would switch them to Jackson 3, which
  is always on the class path because Flyway 12 depends on it, and whose defaults differ (dates
  as text, properties sorted, an error for a null primitive).
- The `Gson` bean the GCP log readers inject now comes from Spring Boot's Gson module
  (`spring-boot-starter-gson`); Spring Boot 3 configured it without one.

### Logging

Logback writes log files in UTF-8 by default. The console uses the console's charset.

## Removed dependencies

| Dependency | Why |
|---|---|
| `io.confluent:kafka-protobuf-serializer` and the Confluent Maven repository | Never referenced; its licence list included the Confluent Community License (Q-107), and it brought the old `swagger-annotations` (Q-272). |
| `io.hypersistence:hypersistence-utils-hibernate-62` | Built for Hibernate 6; its one use is now a Hibernate JSON mapping. |
| `org.springframework.data:spring-data-r2dbc:3.3.2` (da-discovery) | Never referenced, and the Spring Data 3.3 module does not fit Spring Data 2026. |
| `io.dropwizard.metrics:metrics-core` (da-discovery) | Never referenced; its version came from the JHipster 8 BOM, which JHipster 9 no longer publishes. |
| JHipster 8 dependencies BOM (da-discovery) | JHipster 9 publishes no BOM; the Spring Boot BOM applies. |
| Kotlin Gradle plugin 1.9.23 (declared, never applied) | Spring Boot 4 needs Kotlin 2.2 or later; no module compiles Kotlin. |
| `org.glassfish:jakarta.el` and `jakarta.el:jakarta.el-api` (da-discovery, new with Spring Shell 4) | Kept off the class path: Tomcat's EL (`tomcat-embed-el`, Apache-2.0) already provides the same `jakarta.el` classes, so no second copy and no new EPL-2.0 module ships. |

The licence gate no longer carries the Hibernate LGPL exception (`scripts/ci-guards/pre/dependency-licenses.sh`).

## Deprecations to plan for

- Jackson 2 support (`spring-boot-jackson2`, `spring.jackson2.*`, `preferred-json-mapper=jackson2`)
  is deprecated and is to be removed in a later Spring Boot 4.x release. The move to Jackson 3 is a
  separate package (ADR-0066); it must land before the build moves to a Spring Boot release
  without the module.
- Spring Kafka's Jackson 2 `JsonSerializer` and `JsonDeserializer` are deprecated for removal;
  they go with the Jackson 3 move.
- Hibernate's `@GenericGenerator` is deprecated for removal (used by the admin-service and
  da-discovery entities).
- The old starter names (`spring-boot-starter-web`, `-aop`, `-oauth2-*`) still exist in Spring Boot
  4 as deprecated aliases; the build uses the new names.

every service, the licence gate and the regenerated OpenAPI contracts.
